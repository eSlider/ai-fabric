# Мониторинг и Логирование

Для отслеживания работы AI-агентов в системе AI Fabric рекомендуется использовать стандартные инструменты командной строки. Gitea является основным источником правды, а детали выполнения можно увидеть в логах соответствующих сервисов.

## Отслеживание статуса в Gitea

Текущее состояние задачи можно определить по меткам (labels) в Gitea:
- `status:in_progress`: Задача взята в работу (lock; устаревший lock переотбирается через `ISSUE_IN_PROGRESS_TIMEOUT_SEC`).
- `status:pr_opened`: Работа завершена, открыт Pull Request.
- `status:failed`: Произошла ошибка при выполнении.
- `status:failed_max_attempts`: Достигнуто максимальное количество попыток исправления.
- `status:needs_human`: Бюджет авто-исправлений CI исчерпан, архитектор оставил разбор, нужно вмешательство человека.
- `status:completed`: Связанный PR смержен.

Детальный прогресс — в едином статус-комментарии бота на задаче/PR: он
редактируется на месте и содержит скрытый YAML-блок (stage, attempts,
claimed_at, ci_fix, reviewed_shas) плюс краткое резюме. Комментарии задач не
захламляются событиями.

## Просмотр логов через Docker

Если система запущена через Docker Compose, основные логи доступны через команду `docker compose logs`.

### Логи Issue Handler
Отслеживание процесса классификации, планирования (Architect) и вызова агентов:
```bash
docker compose logs -f issue-handler
```

### Логи Gitea Runner
Отслеживание выполнения CI/CD (тесты, линтинг) внутри Gitea:
```bash
docker compose logs -f runner
```

## Использование CLI для фильтрации логов

Вы можете использовать `grep` для быстрого поиска событий без использования AI-агентов.

### Поиск ошибок в логах обработчика
```bash
docker compose logs issue-handler | grep -iE "error|failed|panic"
```

### Отслеживание работы конкретной задачи
```bash
docker compose logs issue-handler | grep "issue #16"
```

### Проверка статуса агента (Cursor Agent)
```bash
docker compose logs issue-handler | grep "runAgent"
```

## Локальные артефакты выполнения

Каждая задача обрабатывается в отдельном рабочем дереве (worktree) в директории `var/agents/issue-<N>/`. Там можно найти:
- `.issue-agent-prompt.md`: Промпт, отправленный разработчику.
- `.issue-architect-prompt.md`: Промпт, отправленный архитектору.
- Исходный код в состоянии на момент выполнения задачи.

Логи выполнения команд внутри агента часто выводятся в stdout/stderr `issue-handler`.
